# Learn SVG Batch

批量并行学习多个微信公众号 SVG 代码，沉淀知识到知识库。

## 触发条件

- 用户提供多个代码文件或代码片段要求批量学习
- 用户指定目录和数量，如"学习 source 目录下前 5 篇"
- 用户说"批量学习"、"并行学习"、"一起学这几个"

## 输入方式

支持三种输入方式：

### 方式一：指定目录 + 数量

用户说：
- "学习 source 目录下前 5 篇"
- "分析 works 下所有 html 文件"
- "学 source 里的前 10 个"

执行步骤：
1. 用 `find` 或 `ls` 扫描目录，列出所有 `.html` 文件
2. 按文件名排序，取用户指定的数量（"前 N 篇"）
3. 逐个读取文件内容
4. 进入并行分析流程

### 方式二：指定多个文件路径

用户直接给多个文件路径：
- "学习 a.html、b.html、c.html"
- "分析这 3 个文件：path1, path2, path3"

### 方式三：直接给代码片段

用户在对话中直接贴多个代码片段。

## 前置要求

- 每个代码必须能独立分析（完整的 SVG 交互动画）
- 如果目录中文件数量不足，告知用户实际数量，按实际数量继续

## 知识库位置

写入目标：`.Codex/skills/create-svg/references/knowledge/`

## 执行流程

### 第一阶段：并行分析

1. 读取 `.Codex/skills/create-svg/references/knowledge/index.md`，了解已有知识库内容
2. 将用户给的代码按文件拆分，每个文件分配一个 Agent
3. 为每个 Agent 构造 prompt，内容包括：
   - 该文件的完整代码
   - 知识库索引内容（用于对比已有知识）
   - 分析指令（见下方 Agent prompt 模板）
4. 使用 Agent 工具**并行启动所有 Agent**（全部设置 `run_in_background: true`）
5. 等待所有 Agent 完成

### 第二阶段：汇总报告

所有 Agent 完成后，汇总每个 Agent 的分析报告，按文件逐一整理。

### 第三阶段：逐个确认入库

对每个分析报告，依次执行：

1. 展示该文件的分析结论（费曼三段式）
2. 询问用户：「以上三种理解方式，有没有不准确的地方？」
3. 用户确认后，展示待入库条目
4. 用户再次确认后，写入知识库
5. 写入完成后输出复盘总结

**注意**：入库必须串行，不能并行写入，避免知识库文件冲突。

### 第四阶段：总复盘

所有文件处理完毕后，输出总复盘：

1. **本次批量学习收获**：总共学到了几个新模式？几个变体？
2. **跨文件关联**：不同文件之间有没有共通的模式或关联？
3. **待验证项汇总**：所有文件中标记为"待验证"的内容汇总
4. **知识库变化**：新增了哪些文件？更新了哪些文件？

## Agent prompt 模板

给每个 Agent 的 prompt 应包含以下内容：

```
你是 SVG 代码分析专家。请分析以下微信公众号 SVG 代码，按严格流程执行。

## 你的任务

按以下步骤分析代码，每一步都不能跳过：

### 步骤一：Survey 浏览
- 快速浏览代码整体结构
- 看 viewBox 尺寸、外层 <section> 和顶层 <g> 的嵌套结构
- 大致判断有哪些模块
- 对比已有知识库索引，找出可能相关的已有模式

已有知识库索引：
{index.md 内容}

### 步骤二：Question 提问
- 列出至少 3 个具体的分析目标问题
- 问题要具体，不要泛泛
- 问题答案由你自己在精读时寻找，不要问用户

### 步骤三：Read 精读
- 逐行阅读每一行代码，不跳过
- 理解每个元素的作用、每个数值的含义、动画的触发条件和时序
- 重点关注步骤二的问题是否找到答案
- 不理解的地方标注出来，不能猜测

### 步骤四：模块划分
- 输出整个代码的模块划分
- 每个模块大概做什么
- 模块之间的嵌套/并列关系

### 步骤五：与已有知识对比
- 每个模块和已有知识对比
- 已有模式 → 看有没有不同之处值得记录
- 全新模式 → 作为新知识学习
- 一个文件可能包含多个模式，拆开分别处理

### 步骤六：识别未知项
- 列出不确定或不理解的内容
- 禁止用"设计值"、"经验值"掩盖没推算出来的公式
- 只有一个样本时标注"待验证"
- 不确定的结论标注"待验证"

### 步骤七：费曼三段式验证
用三种讲法验证理解：

1. **小白讲法**：用完全不懂 SVG 的人能听懂的话解释，不能出现技术术语
2. **技术讲法**：用准确的技术术语描述原理，讲清楚机制
3. **类比讲法**：找一个生活中的类比帮助理解

判定：三种讲法都通过 → 理解合格。任何一种讲不清 → 标记为知识漏洞 → 重新精读。

### 步骤八：输出待入库条目

按以下格式输出：

# 模式名称

## 一句话核心
（这个模式的本质是什么，一句话说清楚）

## 原理
（底层逻辑，掰开揉碎讲清楚）

## 核心代码
（干净的可复用代码片段）

## 关键参数
（通用公式、计算方法、怎么选择值 — 不能是具体数值）

## 变体
（同一个套路，举一反三的应用场景）

## 适用场景
（什么时候用这个模式）

## 质量自检
- [ ] 原理能脱离源代码独立解释
- [ ] 关键参数有明确的通用公式
- [ ] 公式用变量表示，不绑定具体数字
- [ ] 核心代码是干净的可复用模板
- [ ] 变体之间有明确的差异说明
- [ ] 适用场景描述具体
- [ ] 不确定的内容已标注"待验证"
- [ ] 费曼三段式验证全部通过

## 待分析的代码

{代码内容}
```

## 入库原则

与 learn-svg skill 保持一致：

- 只存增量：新模式新建文件，变体追加到已有文件
- 不重复：已有内容不重复写入
- 矛盾时保留两种：讨论差异和适用场景，不覆盖
- 核心是原理和参数：必须掰开揉碎理解清楚后再存
- 不存来源信息：不需要记录参考了哪个源文件
- 只存通用原理：不存从单个样本中提取的具体数值
- 公式必须通用：分母/分子用变量表示，不绑定具体数字

## 知识文件命名规则

- 按交互模式命名，用英文短横线分隔
- 示例：`click-expand.md`、`sequence-frames.md`、`horizontal-scroll.md`

## 注意事项

- 并行分析阶段使用 Agent 工具，所有 Agent 同时启动
- 入库阶段必须串行，一个一个确认写入
- 如果某个 Agent 分析失败，不影响其他 Agent，跳过该文件继续
- 用户可以随时要求跳过某个文件或停止批量学习
