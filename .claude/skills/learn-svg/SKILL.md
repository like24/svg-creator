# Learn SVG

学习微信公众号 SVG 代码，沉淀知识到知识库。

## 触发条件

- 用户给代码片段要求分析
- 用户给完整 HTML 文件要求学习
- 用户讨论后要求沉淀知识

## 知识库位置

写入目标：`.claude/skills/create-svg/references/knowledge/`

## 学习流程

### 第一步：读取已有知识

读取 `.claude/skills/create-svg/references/knowledge/index.md`，了解当前知识库中已有哪些模式。

### 第二步：分析代码

**分析深度**：
- 默认：全部代码逐行分析
- 用户指定：只分析某部分（如"只看滚动部分"、"只看动画逻辑"）

**分析内容**：
- 底层原理：这个效果是怎么实现的，为什么这样写
- 核心代码结构：HTML 壳子、SVG 层叠、动画触发链
- 关键参数：公式、数值来源、怎么计算
- 触发方式：click / touchstart / 自动
- 动画类型：opacity / width / translate / visibility 等

### 第三步：对比已有知识

- 全新模式 → 准备新建知识文件
- 已有模式的变体 → 准备追加到已有文件的变体部分
- 与已有知识矛盾 → 保留两种，准备讨论差异和各自适用场景

**多模式拆分**：如果一个文件包含多个独立模式（如点击展开 + 横向滚动），拆成多个知识条目分别入库，不混在一个文件里。

### 第四步：讨论确认

向用户汇报分析结论，确认理解是否正确：
- 用自己的话描述原理，问用户「这样理解对吗？」
- 对不确定的地方主动提问
- 如果发现和已有知识有矛盾，提出讨论：「这里和已有的 XX 方案不同，原因是...你觉得哪种更适合什么场景？」
- 用户确认理解正确后，再进入下一步

### 第五步：展示待入库条目

向用户展示完整的待写入内容，格式如下：

```markdown
# 模式名称

## 原理
（底层逻辑，掰开揉碎讲清楚）

## 核心代码
（干净的可复用代码片段）

## 关键参数
（公式、计算方法、怎么选择值）

## 变体
（同一个套路，举一反三的应用场景）

## 适用场景
（什么时候用这个模式）
```

如果存在矛盾方案，在变体部分标注：

```markdown
## 变体

### 方案 A：XXX
（代码和说明）
适用场景：...

### 方案 B：YYY
（代码和说明）
适用场景：...
```

### 第六步：用户确认后写入

用户确认内容无误后：
1. 写入或更新知识文件（如 `click-expand.md`）
2. 更新 `index.md` 索引

## 知识文件命名规则

- 按交互模式命名，用英文短横线分隔
- 示例：`click-expand.md`、`sequence-frames.md`、`horizontal-scroll.md`

## 入库原则

- 只存增量：新模式新建文件，变体追加到已有文件
- 不重复：已有内容不重复写入
- 矛盾时保留两种：讨论差异和适用场景，不覆盖
- 核心是原理和参数：必须掰开揉碎理解清楚后再存
- 不存来源信息：不需要记录参考了哪个源文件

## 入库质量自检

写入前必须确认以下全部通过：

- [ ] 原理能脱离源代码独立解释（不看代码也能讲清楚）
- [ ] 关键参数有明确的公式或选择依据（不是"大概这个值"）
- [ ] 核心代码是干净的可复用模板（不是从源文件直接复制的完整代码）
- [ ] 变体之间有明确的差异说明（不是简单罗列）
- [ ] 适用场景描述具体（不是"各种场景都可以用"）
